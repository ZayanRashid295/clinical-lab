\chapter{Results}
\label{ch:results}

This chapter presents qualitative and scenario-based evaluation of MedPrepAI through representative case studies drawn from implemented functionality and demo seed data (\texttt{seed-demo-full.ts}). Quantitative large-scale user trials were outside capstone scope; nevertheless, end-to-end workflows demonstrate that requirements in Tables~\ref{tab:requirements}--\ref{tab:nfr} are satisfiable in production configuration.

\section{Evaluation Approach}
We evaluate along six dimensions:
\begin{enumerate}
  \item \textbf{Functional completeness}: Full encounter, SOAP, resume sessions;
  \item \textbf{Pedagogical mode fidelity}: Distinct UX per MedPrep mode;
  \item \textbf{Institutional workflow}: Faculty metrics and assignments;
  \item \textbf{Platform integration}: LMS + billing + access control;
  \item \textbf{LLM reliability}: Structured outputs with validation/retry;
  \item \textbf{Operational readiness}: Build, deploy, demo seed reproducibility.
\end{enumerate}

Table~\ref{tab:eval-metrics} defines measurable indicators used in case studies.

\section{MedPrep Practice Mode: Case Study}
\subsection{Test Scenario}
A student selects Practice mode (\texttt{/practice-mode}), starts case ``Acute Dyspnea'' (demo seed), and conducts history questions via chat. The frontend calls patient-response APIs; messages persist to \texttt{MedprepConversationMessage} with role PATIENT/STUDENT.

\subsection{Sample Interaction (Illustrative)}
Table~\ref{tab:practice-dialogue} shows an excerpt of a practice encounter (representative structure).

\begin{table}[htbp]
  \centering
  \caption{Excerpt of Practice mode dialogue (illustrative demo).}
  \label{tab:practice-dialogue}
  \small
  \begin{tabular}{@{}p{1.5cm}p{10.5cm}@{}}
    \toprule
    \textbf{Role} & \textbf{Utterance} \\
    \midrule
    STUDENT & When did your shortness of breath start? \\
    PATIENT & About two days ago, worse when I lie flat. \\
    STUDENT & Any chest pain, cough, or leg swelling? \\
    PATIENT & Mild dry cough; my ankles have been swollen this week. \\
    STUDENT & I would like to order a BNP and chest X-ray. \\
    \bottomrule
  \end{tabular}
\end{table}

\subsection{Observed Outputs}
\begin{itemize}
  \item Conversation remains ACTIVE until explicit completion.
  \item Diagnosis submission records \texttt{isCorrect} against ground truth.
  \item SOAP note saved with student fields; AI rubric fields populate after grading API.
  \item Achievement \texttt{MEDPREP\_FIRST\_CASE} increments activity counters.
\end{itemize}

\subsection{Discussion}
Practice mode satisfies Objective~1. Entitlement guard denies mode when subscription lacks \texttt{let-me-drive} slug---confirming governance (Objective~4). Measured outcome: pass on functional and integration dimensions.

\section{LMS Question Bank: Case Study}
\subsection{Test Scenario}
Admin imports Markdown/DOCX batch; student with Qbank entitlement builds 40-item timed paper.

\subsection{Performance Analytics}
After submission, results page reports:
\begin{itemize}

  \item Time per question;
  \item Flagged items for review (bookmark integration).

\subsection{Discussion}
LMS pipeline satisfies Objective~2; platform is not limited to four MedPrep modes.

\section{DOCX Import: Case Study}
\subsection{Test Scenario}
Faculty uploads DOCX examination document with five MCQs and image explanations.

\subsection{Observed Outputs}
Parser extracts five \texttt{Question} rows with linked \texttt{QuestionChoice} records; images stored with corrected URLs per \texttt{IMAGE\_UPLOAD\_FIX} deployment notes.

\subsection{Discussion}
Content pipeline reduces authoring time---critical for institutional adoption where faculty lack SQL skills.

\section{AI Tutor: Case Study}
\subsection{Test Scenario}
Student asks mechanism question on heart failure and BNP.

\subsection{Observed Outputs}
Gemini answer explains natriuretic peptide release; conversation stored under \texttt{AiTutorConversation}. Missing API key triggers offline fallback (logged warning, no crash).

\subsection{Discussion}
Modular tutor separation reduces prompt injection between patient and tutor roles.

\section{Payments and Entitlements: Case Study}
\subsection{Test Scenario}
Student purchases Premium; attempts Shadow mode (previously blocked).

\subsection{Observed Outputs}
\texttt{getUserActiveFeatures} includes \texttt{shadow-mode}; \texttt{POST /medprep-ai/sessions} succeeds. Invoice row visible on \texttt{/payments/history}.

\subsection{Discussion}
Commercial viability (Objective~4) demonstrated---important for sustainable institutional licensing.

\section{Chat and Notifications: Case Study}
\subsection{Test Scenario}
Faculty sends message to student; student receives in-app notification.

\subsection{Observed Outputs}
\texttt{ChatMessage} created with \texttt{FACULTY\_STUDENT} room type; notification preference respected; realtime socket event delivered when connected.

\subsection{Discussion}
Clinical workflow includes communication---not only simulation silos.
